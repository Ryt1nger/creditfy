# Кредитный кабинет предпринимателя — демо-прототип (Альфа-Банк · хакатон «Альфа Будущее»)

Цифровой кредитный конвейер для малого и микробизнеса: клиент проходит путь от потребности до денег на счёте, а банк
управляет этим же процессом в одном продукте. **Все данные синтетические, внешние сервисы (ЕГРЮЛ, БКИ, ФНС) — локальные симуляторы,
подписание и выдача — симуляция, условия продуктов — демо, не реальные предложения банка.** Прототип не является реальным сервисом банка.

**Что внутри:** квиз «опишите задачу» (по одному вопросу на экран, только недостающее) → портрет задачи → подбор (1 главный + 2 запасных, «Почему подходит») →
мастер заявки в режиме фокуса (сумма/срок → компания по ИНН и заявитель → документы → проверка данных с источником каждого числа → отправка) → статусы с пояснением
«что происходит / нужно ли ваше действие» → кабинет банка. Скоринг — не решение; ИИ решений не принимает. Локальная модель с открытыми весами **выключена по умолчанию**,
всё работает на правилах и банке вопросов.

## Быстрый старт

**Вариант 1 — Docker (полный стек: Postgres + API + веб):**
```bash
docker compose up --build
# открыть http://localhost:8080
# опционально — локальная модель (DeepSeek-R1 distill через Ollama), по умолчанию выключена:
LLM_ENABLED=1 docker compose --profile llm up --build -d
docker compose exec ollama ollama pull deepseek-r1:1.5b
```
**Вариант 2 — без Docker:**
```bash
# бэкенд (Python 3.10+)
cd backend && python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements-dev.txt
uvicorn app.main:app --port 8000          # Swagger UI: http://localhost:8000/docs
# фронтенд (Node 20+), в другом терминале
cd frontend && npm ci && VITE_API_MODE=live npm run dev    # http://localhost:5173
```
**Вариант 3 — только фронтенд на встроенных демо-данных (без бэкенда):** `cd frontend && npm ci && npm run dev`.
Движок в браузере (`src/mock`) повторяет логику бэкенда; состояние хранится в localStorage, сброс — ссылка «Сбросить демо-данные» внизу.

## Облачная демонстрация (Render, бесплатный тариф)
* Веб: https://creditfy-web.onrender.com · API и Swagger: https://creditfy-api.onrender.com/docs (логины ниже, пароль `demo123`).
* Статический сайт (`frontend`, `VITE_API_MODE=live`, `VITE_API_BASE`) + Docker-сервис API (`backend/Dockerfile`), SQLite внутри контейнера, модель выключена (`LLM_ENABLED=0`).
* Бесплатный тариф засыпает: первый запрос после простоя идёт ~50 с; при пересборке или перезапуске SQLite и загруженные файлы сбрасываются, демо-данные создаются заново.
* Сквозная проверка: `python backend/scripts/e2e_live.py https://creditfy-api.onrender.com`.

## Помощник с готовыми ответами (без ИИ)
В строке «Опиши задачу» и по кнопке «Помощь» можно задать вопрос: «какие у вас кредиты?», «какая ставка?», «какие нужны документы?», «сколько ждать?», «нужен ли залог?». Помощник отвечает готовыми демо-текстами по ключевым словам (`backend/app/config_data/faq.json`, `POST /api/assistant/ask`); ответы помечены «готовый демо-ответ (без ИИ)», цифры берутся из каталога продуктов. Описание задачи («купить печь, 2 млн на 3 года») по-прежнему запускает квиз. Позже тексты и условия правятся в `faq.json` и `products.json`.

## Вход и регистрация
Экран входа без готовых профилей: выберите роль (**Предприниматель** или **Сотрудник банка**), затем «Войти» или «Зарегистрироваться». Регистрация — имитация внутри продукта: форма → шаги «Проверяем данные / Создаём профиль / Подтверждаем кабинет (симуляция)» → вход; почта, SMS и звонки не используются. Новый предприниматель получает пустой кабинет, новый сотрудник банка — роль андеррайтера (`POST /api/auth/register`, пароль от 6 символов).

## Пошаговая проверка основного сценария (5 минут)
1. Войдите как `ivan@demo.ru` → «Подать заявку» (или на главной опишите задачу в строке помощника).
2. Введите: *«Нужно 1,5 млн на закупку товара к сезону, на 2 года»*. Цель, сумма и срок поняты из текста — квиз спросит только форму бизнеса (ООО) и его возраст (1–3 года), по одному вопросу на экран.
3. «Вот что мы поняли» — портрет задачи (у каждого значения видно, откуда оно: из текста или ваш ответ; можно изменить) → «Показать подбор»: главный вариант «Оборотный кредит» с блоком «Почему подходит» и два запасных → «Оформить этот».
4. Откроется мастер в режиме фокуса (без вкладок и подвала; вверху прогресс «Шаг N из 5», оценка времени, «Сохранено», «Сохранить и выйти»). **Шаг 1:** сумма и срок уже подставлены. **Шаг 2:** ИНН `7804123453` (Север-Логистика), ФИО, телефон, роль.
5. **Шаг 3:** «Приложить демо-комплект» — загрузятся синтетические выписка (XLSX) и отчётность (PDF); числа распознаются парсерами. **Шаг 4:** у каждого числа подпись источника («Отчётность, строка 2110…»). **Шаг 5:** согласие → «Отправить заявку».
6. Статус пойдёт сам (проверка данных → реестры → скоринг → «Банк одобрил»); в карточке видно «Что происходит» и «Нужно ли действие от вас». «Принять условия» → «Подписать и получить деньги» → «Кредит выдан», внизу график платежей.
7. **Расхождение:** повторите с ИНН `500123456750` (ИП Волков): после демо-комплекта шаг 4 покажет «Требует проверки» (оборот×12 расходится с выручкой на 47%). Отправка заблокирована, пока вы не исправите значение или не нажмёте «Подтвердить, что верно».
8. **Продолжить позже:** на любом шаге нажмите «Сохранить и выйти» — в «Мои заявки» и на главной появится «Продолжить с шага N».
9. Выйдите, войдите как `risk@demo.ru`: очередь, ручной разбор заявки ИП Волкова, скоринг по факторам, решение. Вкладка «Аналитика» — воронка.
10. Свои файлы: любой текстовый PDF/XLSX/CSV с кодами строк 2110/2400 (отчётность) или таблицей «Месяц · Поступления · … платежи по кредитам» (выписка). Образцы для всех демо-ИНН: `cd backend && PYTHONPATH=. python -m app.documents.samples --out ../samples`.

## Окружение и конфигурация
Python ≥3.10 (в Docker 3.12), Node ≥20, версии зафиксированы: `backend/requirements.txt`, `frontend/package-lock.json`. Переменные — `.env.example`:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DATABASE_URL` | SQLite `./data/creditfy.db` (в Compose — Postgres) | БД |
| `JWT_SECRET` | dev-значение | подпись токенов (замените вне демо) |
| `PIPELINE_STEP_DELAY` | `0.9` | пауза между шагами конвейера, чтобы статус менялся «вживую» (в тестах 0) |
| `UPLOAD_DIR`, `SEED_DEMO` | `./data/uploads`, `1` | файлы и демо-данные |
| `LLM_ENABLED` | `0` | включить локальную модель |
| `LLM_BASE_URL` | `http://localhost:11434/v1` | OpenAI-совместимый адрес Ollama |
| `LLM_MODEL` | `deepseek-r1:1.5b` | модель |
| `LLM_MAX_CALLS` / `LLM_TIMEOUT` | `3` / `8` | бюджет вызовов на сессию и таймаут, с |

Секретов в репозитории нет. Каталог продуктов и реестр полей квиза — `backend/app/config_data/*.json` (копия для демо-режима — `frontend/src/config`, равенство проверяет тест).

## Ограничения
* Только синтетические данные; ЕГРЮЛ/БКИ/ФНС — симуляторы; подпись и выдача — симуляция; почты, SMS и звонков нет, интерфейс только веб.
* Модель с открытыми весами необязательна и выключена по умолчанию; платных API нет. Режим «без бэкенда» (`npm run dev` без `VITE_API_MODE=live`) имитирует ИИ-формулировки и распознавание документов — они помечены как имитация.
* Docker проверен: `docker compose up --build` (Postgres 16 + API + nginx) собирается и запускается, `backend/scripts/e2e_live.py http://localhost:8080` проходит. Профиль `llm` (Ollama) и реальная модель не запускались.
* Распознавание документов — только текстовые PDF, XLSX, CSV; OCR сканов нет (поля остаются пустыми, клиент вводит их на шаге проверки).
* Нет refresh-токенов, ограничения частоты входа, антивируса для файлов и реального ЭП — это явно вынесено за рамки прототипа (`docs/architecture.md`, раздел «Enterprise»).
