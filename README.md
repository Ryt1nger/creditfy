# Кредитный кабинет предпринимателя — демо-прототип (Альфа-Банк · хакатон «Альфа Будущее»)

Цифровой кредитный конвейер для малого и микробизнеса: клиент проходит путь от потребности до денег на счёте, а банк
управляет этим же процессом в одном продукте. **Все данные синтетические, внешние сервисы (ЕГРЮЛ, БКИ, ФНС) — локальные симуляторы,
подписание и выдача — симуляция.** Прототип не является реальным сервисом банка.

## Быстрый старт

**Вариант 1 — Docker (полный стек: Postgres + API + веб):**
```bash
docker compose up --build
# открыть http://localhost:8080
```
**Вариант 2 — без Docker:**
```bash
# бэкенд (Python 3.10+)
cd backend && python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements-dev.txt
uvicorn app.main:app --port 8000          # Swagger UI: http://localhost:8000/docs
# фронтенд (Node 20+), в другом терминале
cd frontend && npm ci && VITE_API_MODE=live npm run dev    # http://localhost:5173
```
**Вариант 3 — только фронтенд на встроенных демо-данных (без бэкенда):** `cd frontend && npm ci && npm run dev`.
Движок в браузере (`src/mock`) повторяет логику бэкенда; состояние хранится в localStorage, сброс — ссылка «Сбросить демо-данные» внизу.

## Пошаговая проверка основного сценария (5 минут)
1. Войдите как `ivan@demo.ru` → «Подать заявку».
2. Шаг 1: опишите задачу («закупить товар к сезону») → «Подобрать продукт» (ИИ-заглушка) → продолжить. Шаг 2: сумма 2 000 000 ₽, срок 24 мес.
3. Шаг 3: нажмите демо-ИНН «Север-Логистика». Шаг 4: выручка 60 000 000, прибыль 9 000 000, оборот 5 000 000, платежи 150 000, любой контакт.
4. Шаг 5: загрузите один документ «Образец», остальные пропустите → отправьте. Заявка **остановится на «Нужны уточнения»** (банк требует недостающее).
5. В карточке заявки приложите оставшиеся документы → «Отправить ответ». Статус пойдёт сам: проверка данных → реестры → скоринг → «Банк одобрил».
6. «Принять условия» → «Подписать и получить деньги» → «Кредит выдан», внизу график платежей.
7. Выйдите, войдите как `risk@demo.ru`: в очереди — заявка ИП Волкова на ручном рассмотрении. Откройте её: скоринг по факторам, данные реестров, сводка (ИИ-заглушка).
   Нажмите «Запросить данные у клиента» либо «Одобрить» / «Свое встречное предложение» / «Отказать». Клиент увидит решение и причину.
8. Вкладка «Аналитика»: воронка и доля автоматических решений.

## Состав репозитория
| Путь | Что внутри |
|---|---|
| `backend/` | FastAPI, SQLAlchemy, конвейер (`app/services`), симуляторы (`app/integrations`), ИИ-слой (`app/ai`), тесты (`tests`) |
| `frontend/` | React + TypeScript + Vite, дизайн в стиле Альфа-Банка (`src/styles.css`), демо-движок (`src/mock`) |
| `docs/` | `REPORT.md` (отчёт), `architecture.md`, `state-diagram.md`, `data-model.md`, `openapi.json`, `test-scenarios.md`, `ai-integration.md`, `research.md`, `design-system.md`, `api/creditfy.postman_collection.json` |
| `docker-compose.yml` | Postgres + backend + nginx с фронтендом |

## Проверки
```bash
cd backend && pytest -q          # 10 сквозных тестов: автоодобрение, отказы, встречное, цикл уточнений, права доступа, загрузка
cd frontend && npm test && npm run typecheck && npm run build
```

## Окружение и конфигурация
Python ≥3.10 (в Docker 3.12), Node ≥20, версии зафиксированы: `backend/requirements.txt`, `frontend/package-lock.json`. Переменные — `.env.example`
(`DATABASE_URL`, `JWT_SECRET`, `PIPELINE_STEP_DELAY`, `LLM_PROVIDER`, `UPLOAD_DIR`, `SEED_DEMO`). Секретов в репозитории нет.

## Ограничения
* ИИ — заглушка (`LLM_PROVIDER=stub`); адаптер DeepSeek (open weights, локально) запланирован: `docs/ai-integration.md`.
* Docker-конфигурация написана, но в среде разработки собрать образы не удалось (нет демона Docker) — проверьте `docker compose up --build` у себя.
* Нет refresh-токенов, ограничения частоты входа, антивируса для файлов и реального ЭП — это явно вынесено за рамки прототипа (см. `docs/architecture.md`, раздел «Enterprise»).
