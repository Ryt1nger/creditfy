# План разработки ядра (утверждён владельцем)

## Идея пути клиента
Заявка — единый объект данных. Клиент пишет задачу своими словами → короткий квиз (только недостающее, по одному вопросу на экран, ответ карточкой) → «портрет задачи» → подбор (1 главный + 2 запасных варианта) → выбор → оформление в фиксированном порядке → отправка → статусы. Система ведёт клиента к завершению: режим фокуса, прогресс и оценка времени, автосохранение, «Продолжить с шага N», без ложной срочности.

## Слои ИИ: правила первыми, модель точечно
| Слой | Кто |
|---|---|
| Разбор запроса (цель, сумма, срок, ИП/ООО, возраст бизнеса) | Правила (`frontend/src/lib/need.ts` → перенести на бэкенд). Модель — только если остались пробелы и текст свободный |
| Что спросить | Реестр полей (конфигурация): какие поля пусты и влияют на подбор |
| Формулировка вопросов квиза | Банк готовых вопросов с карточками-ответами; модель пишет вопрос в контексте и 1 уточняющий там, где двусмысленно. Макс. 3 вызова на сессию, таймаут 8 с, откат на банк |
| Портрет задачи, подбор, «Почему подходит» | Правила и шаблоны |
| Извлечение чисел из документов | Парсеры (текстовые PDF, XLSX, CSV); модель — запасной вариант; проверка по схеме и перекрёстная проверка |
| Скоринг, кредитное решение, конвейер, статусы | Только правила |
| Помощник «Нужна помощь?», сводка для специалиста | Модель, вторая очередь |

Модель: локальная модель с открытыми весами, **локально** (Ollama, `` дистиллят 1.5B/7B), OpenAI-совместимый адрес из переменных `LLM_ENABLED`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_MAX_CALLS=3`, `LLM_TIMEOUT=8`. По умолчанию выключена. Вывод — JSON по схеме, вопрос обязан ссылаться на поле из белого списка, иначе берём банк. В модель не отправляем ИНН/телефон/ФИО (маскирование). Текст клиента — данные, не инструкции. Вырезать `<think>…</think>`. Логировать вызовы в `ai_calls`.

## Данные
`intake_sessions` (текст, извлечённые поля, ответы, портрет, шаг, application_id), `intake_turns` (вопрос, поле, варианты, ответ, источник ai|bank), `ai_calls`, `doc_extractions` (document_id, field, value, source, confidence, status ok|edited|conflict|confirmed). Реестр полей и каталог продуктов — конфигурация (JSON/YAML), грузится в БД.

API: `POST /intake/start`, `POST /intake/{id}/answer`, `GET /intake/{id}`, `POST /intake/{id}/recommend`, создание заявки из сессии, `POST /applications/{id}/documents` (возвращает извлечённые поля), `PATCH /extractions/{id}`.

## Порядок оформления после выбора продукта
1. Сумма и срок (подтвердить, подставлено из квиза) → 2. Компания по ИНН (+ ФИО/телефон/роль заявителя) → 3. Документы (только нужные продукту; «распознавание») → 4. Проверка данных (значения из документов с подписью источника, редактируемые; пустые подсвечены; расхождение оборот×12 vs выручка >35% = «Требует проверки», нужно подтвердить) → 5. Итог и отправка (согласие, без автоотправки).
Документы по продукту: выписка и отчётность всегда; бизнес-план для инвестиционного; счёт/договор для оборудования; документы на залог при залоге.

## Каталог продуктов
ТЗ каталога не задаёт — придумываем сами, всё с пометкой «демо-условия, не реальные предложения банка». Сайт alfabank.ru закрыт для автоматического чтения (robots), поэтому условия владелец может прислать вручную (текст/скриншоты) — тогда сверить диапазоны и поля формы. Иначе используем реалистичные демо-диапазоны. Сейчас 4 продукта в `backend/app/products.py` и `frontend/src/mock/products.ts` — вынести в файл каталога + условия допуска (формы ИП/ООО, минимальный возраст бизнеса, залог).

## Этапы
1. Основа: реестр полей, каталог, схемы, миграции/таблицы, адаптер локальной модели (с заглушкой, валидацией, бюджетом, кэшем).
2. Движок квиза: правила разбора, банк вопросов, ИИ-вопросы, портрет, подбор.
3. Документы: парсеры, запасной ИИ, правило расхождений, статусы подтверждения; генератор синтетических PDF/XLSX под демо-ИНН (один комплект с расхождением).
4. Фронтенд: квиз (по одному вопросу на экран), портрет, подбор, мастер в режиме фокуса, автосохранение и «Продолжить», шаг проверки данных с источниками, пояснения статусов.
5. Паритет mock-режима для превью (вопросы из банка, ИИ помечен как имитация).
6. Тесты (разбор, валидация, бюджет, контрактный тест с фейковой моделью), обновить `docs/REPORT.md`, README, THIRD_PARTY_NOTICES, OpenAPI, схемы.
7. Docker (compose: web, api, опционально ollama) — проверить реально, `git init`, GitHub-репозиторий `Ryt1nger/creditfy` (приватный, доступ для `alfa-hack-2026`).
8. Облако (по желанию): Render — статика, API + Postgres, приватный сервис Ollama (CPU, 1.5B, платный тариф от 4 ГБ). Это только демонстрация, проверяемая версия от неё не зависит.
