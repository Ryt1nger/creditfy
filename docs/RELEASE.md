# Creditfy v1.0.0-hackathon — 26.10.2026

Релиз для сдачи. Точный commit закреплён тегом v1.0.0-hackathon в GitHub.

## Изменения
- Вход и регистрация с проверкой /me; автоматическое определение серверной роли; понятный выбор типа кабинета; готовый клиентский кабинет без регистрации.
- Запрет публичной регистрации банковских ролей; нормальная обработка неправильного JWT; очистка кэша при смене пользователя.
- Ограничения сумм и сроков, защита от отрицательных обязательств, валидация null, корректное открытие незаполненного черновика сотрудником.
- Ограниченные повторы обработки и восстановление после перезапуска; ручная кнопка повтора при технической остановке.
- Проверка документов только на стадии рассмотрения; полный график платежей.
- Публичные базовые программы до 30 млн ₽ без залога и до 150 млн ₽ с залогом, отдельные скидочные ставки и источники. Старые условия сохраняются в снимках заявок, предложения и кредиты не пересчитываются.
- Овердрафт информационный: новый аннуитетный расчёт и оформление отключены.
- Убраны названия моделей и повторяющиеся технические пометки. Пояснение о синтетических данных и смоделированных операциях оставлено внизу страницы.
- Анимация пути заявки продолжает работать при наведении.
- Docker/PostgreSQL, CI, OpenAPI/Postman, Render Blueprint и README для жюри.

## Проверки
- Backend: 77 тестов пройдены на локальном Python 3.14.
- Frontend: 43 теста пройдены; npm ci и production build выполнены.
- Docker: образы Python 3.12/Node 22 собраны, PostgreSQL/API/nginx запущены на localhost:8088; проверка конвейера через nginx выполнена.
- Браузер: регистрация синтетического нового клиента и проверка серверной сессии выполнены.
- Перед изменением видимости проверены отслеживаемые файлы: приватные ключи, токены, БД и .env не обнаружены. Это проверка распространённых шаблонов, не полный аудит безопасности.

## Границы
Публичный Render требует постоянной PostgreSQL для сохранности регистраций. Обновление приложения само по себе не заменяет настройку DATABASE_URL. render.yaml подготовлен; существующие сервисы он автоматически не перенастраивает. Реальные финансовые операции, OCR и распределённый конвейер вне MVP. API запускается одним worker.
