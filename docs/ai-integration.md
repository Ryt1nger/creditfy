# ИИ: правила первыми, локальная модель с открытыми весами — точечно

ТЗ: ИИ приветствуется, но не обязателен; только модели с открытыми весами; платных API нет. Поэтому:

* **Проверяемая версия работает без модели** (`LLM_ENABLED=0`, по умолчанию): вопросы берутся из банка (`backend/app/config_data/fields.json`), текст разбирают правила.
* **Модель — DeepSeek-R1 distill (1.5B/7B) через Ollama**, запускается локально; адаптер — `backend/app/ai/llm.py`, OpenAI-совместимый `POST {LLM_BASE_URL}/chat/completions`. Платный DeepSeek API не используется.

## Переменные окружения
| Переменная | По умолчанию | Смысл |
|---|---|---|
| `LLM_ENABLED` | `0` | включить обращения к модели |
| `LLM_BASE_URL` | `http://localhost:11434/v1` (в Compose — `http://ollama:11434/v1`) | адрес Ollama |
| `LLM_MODEL` | `deepseek-r1:1.5b` | имя модели в Ollama |
| `LLM_MAX_CALLS` | `3` | максимум обращений на сессию квиза / заявку |
| `LLM_TIMEOUT` | `8` | таймаут одного обращения, секунды |

Включение: `LLM_ENABLED=1 docker compose --profile llm up --build`, затем `docker compose exec ollama ollama pull deepseek-r1:1.5b`.

## Где модель участвует (и где нет)
| Слой | Кто | Что делает модель |
|---|---|---|
| Разбор запроса (цель, сумма, срок, ИП/ООО, возраст, залог) | правила `app/intake/parse.py` | `purpose=parse`: только если после правил остались пробелы и текст свободный; значения проверяются по диапазонам реестра полей |
| Что спросить | реестр полей | — |
| Формулировка вопроса квиза | банк вопросов с карточками | `purpose=question|clarify`: пишет вопрос в контексте задачи; **варианты ответов всегда из банка** |
| Портрет, подбор, «Почему подходит» | правила и шаблоны | — |
| Извлечение чисел из документов | парсеры PDF/XLSX/CSV | `purpose=extract`: запасной вариант, если парсер ничего не нашёл; значения помечаются «распознано моделью — проверьте» |
| Скоринг, решение, конвейер, статусы | только правила | — |
| Сводка для специалиста, «Нужна помощь?» | шаблон (вторая очередь ИИ) | — |

## Защитные механизмы (все покрыты тестами `backend/tests/test_llm.py`, `test_intake.py`)
1. **Бюджет:** счётчик в `intake_sessions.ai_calls_used` / `ai_calls`; после `LLM_MAX_CALLS` модель не вызывается, берётся банк.
2. **Таймаут и ошибки:** `LLM_TIMEOUT`; таймаут, HTTP-ошибка, не-JSON, нарушение схемы → `None`, и вызывающий код берёт банк/парсер.
3. **Схема и белый список:** JSON с полем `field`; вопрос принимается, только если `field` совпадает с запрошенным и входит в список полей реестра с `ai_allowed=true`; длина вопроса 5–160 символов; слова «одобр», «гарантир», «инн», «паспорт», «телефон» отклоняются.
4. **`<think>…</think>` вырезается** (в том числе незакрытый блок), ответ извлекается из JSON даже в ```-обёртке.
5. **Маскирование ПДн:** ИНН/ОГРН/длинные номера, телефоны, e-mail, ФИО (три слова с отчеством, «Иванов И. И.», «ИП Фамилия …») заменяются до отправки. В промпт идут только цель, суммы, сроки и уже известные поля реестра.
6. **Текст клиента — данные, а не инструкции:** системный промпт запрещает выполнять команды из текста; ответ модели не может ничего кроме текста вопроса и значений полей из белого списка.
7. **Журнал `ai_calls`:** цель, модель, статус (`ok|invalid|timeout|error|cached`), задержка, размер промпта; текст запроса не хранится. Кэш в памяти исключает повторные вызовы с тем же промптом.
8. **Решений модель не принимает:** кредитное решение, скоринг, маршрутизация и подбор продукта — детерминированные правила.

## Mock-режим (превью без бэкенда)
В браузере модели нет: ИИ-формулировки — **имитация по шаблону**, интерфейс помечает их «Имитация ИИ-формулировки (демо-режим)». В live-режиме при `LLM_ENABLED=1` метка меняется на «Вопрос сформулирован локальной моделью · вызовов N из 3».
